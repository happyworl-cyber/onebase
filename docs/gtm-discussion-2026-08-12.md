# OneBase 市场策略讨论稿（2026-08-12）

> 状态：讨论稿 / 待对齐。记录本轮就「从技术就绪到第一个客户」的讨论过程、结论与待决事项。
> 结论沉淀见 `docs/go-to-market.md`（一页纸）。本文保留推理过程与分歧点。

## 背景

代码侧（License 授权层、代码隔离、token 前缀去血缘）已就绪并推送。卡点不在技术，而在「客户怎么看到、怎么试、渠道怎么卖」。现状约束：香港主体、暂无境内主体、渠道驱动、私有化为主。

---

## 议题一：下一步做什么？要不要做 Demo？官网怎么写？

**讨论**
- 私有化为主的打法，需要的是「先看后试再买」的链路，不是公网多租户 SaaS。
- 注册登录 / 计费 / 多租户在私有化阶段可缓，别拖住找第一个客户。

**结论**
- Demo 三件套：① Demo 视频（必做，渠道转发）→ ② 在线体验 sandbox（warn 模式、每日重置）→ ③ 30 天 POC License（内网试用，临门一脚）。
- 官网＝一页落地页；CTA 只做「预约演示 / 联系渠道」，不放自助注册。
- 唯一真正的里程碑：拿下第一个 POC。

**待决**
- sandbox 现在做还是等第一个 POC 后再做（成本 vs 获客价值）。

---

## 议题二：首页没说服力，怎么改？

**问题**：原首屏在讲「我是什么、有哪些功能」，说服力弱。

**讨论**：决策者掏钱前只关心四件事——省我多少、数据丢不丢、出事谁扛、凭什么信你。

**结论**：首屏改为「先讲结果 + 去风险，再列功能」。
- 主标题：建库即得数据后端，私有部署、随时可交付。
- 量化证据：省 6–12 个月自研 / 100% 内网 / 4–5 合 1。
- 去风险：先跑 30 天 POC 再采购；原厂 + 渠道双售后；License 离线可控可审计。

**缺口（现状短板）**：还没有标杆案例和真实数字。第一个 POC 跑完做成脱敏案例，说服力再上一个台阶。

---

## 议题三：没有境内主体、网站在海外，行不行？

**结论：短期可行**，靠渠道（境内主体）签约、开票、收人民币、离岸结算，这条链本身绕开了「没主体」。

**要点**
- 海外服务器不需要 ICP 备案；域名用 `.com`。
- 海外站不收集境内个人信息、不收人民币，CTA 只留资 + 联系渠道。
- 访问速度：让渠道用其境内主体备案一个国内落地页镜像，或站点放香港/新加坡节点 + CDN。
- 软著 / 商标尽早办（可境内代理登记），利于渠道投标背书。

**真短板**：信创 / 央国企资质门槛——那类单交给渠道顶资质，或等确定性大单再补境内主体。

---

## 议题四：目标客群一定是政企吗？

**修正**：此前把「政企/信创」当主战场是过度假设；用户只说过「企业」。政企对当前现状（无主体、要快出单）门槛最高、周期最长。

**决策：主打前三类**
1. 软件公司 / SI / 外包 —— 私有交付天然刚需、决策快、可复制、渠道对口。
2. 传统企业 IT / 数字化 —— 数据留在自己机房、要快上线、人手不够。
3. AI 应用团队 / ISV —— 要「数据 + 工具（MCP）」层、私有可控。

政企 / 信创降级为**机会型**（渠道有资源时接），非定位主线。首页据此去掉信创话术绑定，改用通吃三类的统一主线 + 三段客群卡。

---

## 议题五：上架阿里云云市场会走量更好吗？

**结论：不是走量引擎**。高价 + 私有化 + 要实施的产品，成交不在商品页。

**定位**：背书 + 线索入口 + 合规回款通道。
- 入驻需境内主体 + 软著（可借渠道主体上架）。
- 云市场镜像跑在阿里云上，与「数据在客户自己机房」存在形态错配——上架的更可能是标准版 / 试用版。
- 抽佣会叠加渠道分润，挤压高价私有化单的毛利。

**玩法**：标准版 / 试用版上架增信获客；私有化大单绕开抽成、走渠道线下成交。

**优先级**：P2 增信补充，非现在；等有 1–2 个标杆 + 软著 + 主体路径后再上。

---

## 结论汇总

1. 打法：私有化为主、渠道驱动，先拿第一个 POC。
2. 客群：软件公司/SI · 传统企业 IT · AI 团队；政企机会型。
3. 定位：建库即得数据后端，私有部署、随时可交付。
4. 触达：Demo 视频 + sandbox + 30 天 POC；.com 落地页做增信留资。
5. 合规：短期靠渠道兜主体；软著/商标尽早办；主体按拿单情况再补。
6. 云市场：P2 增信，非走量。
