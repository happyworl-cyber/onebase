# 云日志查询时间窗放宽到 7 天 — 设计文档

- 日期：2026-09-14
- 状态：已通过
- 范围：站内阿里云 SLS 查询的单次时间跨度上限，从 24 小时改为 7 天。默认窗口、返回行数、凭证与日志源不变。
- 相关代码：
  - `src/cloud_log.rs`
  - `frontend-nextjs/app/workspace/[projectId]/cloud-logs/page.tsx`
- 关联：`docs/superpowers/specs/2026-09-11-project-cloud-logs-design.md`

## 1. 背景

云日志页选稍长于 24 小时的范围会 400：「时间窗不能超过 24 小时」。该上限是站内产品闸门（控费用与超时），不是 GetLogs 请求参数的硬限制。排障经常要跨一天以上对 `x_request_id`。

完全不设上限不合适：SLS 同步查询约 55 秒超时，空白 `*` 扫过长窗口费用高。

## 2. 决定

| 项 | 结论 |
|---|---|
| 单次最长 | **7 天**（`7 * 86400` 秒） |
| 默认 | 仍最近 **1 小时** |
| 行数 | 仍默认 50、上限 100、最新在前 |
| 查询方式 | 仍一次 GetLogs，不按天拆请求再合并 |
| 超时 / SLS 错误 | 沿用现有错误回传，不额外重试 |

超 7 天仍 400，文案改为「时间窗不能超过 7 天」。

## 3. 改动

**后端** `src/cloud_log.rs`：`MAX_WINDOW_SECS = 7 * 86400`；`resolve_query_window` 比较与错误字符串跟着改。单测：默认窗仍 1 小时；刚好 7 天通过；7 天 + 1 秒拒绝。

**前端** 云日志页：开始/结束旁注明「单次最长 7 天」。点查询时若跨度 > 7 天，先 toast 同一文案，不发请求。不改默认起止时间。

不改控制台深链生成（仍用本次 `from`/`to`）。不改网关监控等其它 24h 窗口。

## 4. 非目标

- 30 天或无限窗口
- 服务端按 24h 切片合并
- 提高 `line` 上限
- 切 GetLogsV2
