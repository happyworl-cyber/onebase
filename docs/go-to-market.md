# OneBase 市场策略（GTM）一页纸

> 面向：产品/销售/渠道对齐。私有化为主、渠道驱动、香港主体 + 暂无境内主体的现状下的打法。

## 一、产品定位

**建库即得数据后端，私有部署、随时可交付。**

关系数据库自动生成 REST / 实时 API，内置权限、工作流与 AI（MCP）接入。把 Supabase 级的开发效率装进客户自己的机房——省掉 6–12 个月自研，还能打包私有交付给客户。

三个量化证据（首页主打）：

- **6–12 个月**：省下的后端自研周期
- **100% 内网**：数据留在自己机房 · 私有可交付
- **4–5 合 1**：替代 API 网关 + 权限 + 实时 + 编排 + 存储接入

## 二、目标客群（主打前三类）

| 客群 | 最痛的点 | 一句话卖点（官网场景段 / 渠道话术） |
|---|---|---|
| 软件公司 / SI / 外包 | 每个项目都要重造后端，交付慢、维护重 | 把 OneBase 当标准后端底座：建库即得 API、私有交付给甲方，一套方法交付 N 个项目 |
| 传统企业 IT / 数字化 | 内部系统多、数据要留在自己机房、后端人手不够 | 不扩后端团队也能快速上线内部数据服务，数据 100% 留在自己内网 |
| AI 应用团队 / ISV | AI 要接数据和工具，自己拼一套又慢又不可控 | 现成的数据 + 工具（MCP）层，私有可控，让 AI 应用直接连业务数据 |

> 政企 / 信创：最吃数据主权，但要境内资质、周期长——当**机会型**单子接（渠道有资源时），**不作为主战场**。

## 三、官网怎么写

首屏遵循「先讲结果 + 去风险，再列功能」：

- **主标题**：建库即得数据后端，私有部署、随时可交付
- **副标题**：关系库自动生成 REST/实时 API，内置权限、工作流与 AI（MCP）接入——省掉 6–12 个月自研，还能打包私有交付给你的客户。
- **CTA**：预约演示 / 联系渠道（不放公网自助注册，避免稀释私有化定位）

主标题备选（按主打客户挑）：

1. 建库即得数据后端，私有部署、随时可交付（通用主线，推荐）
2. 把一个后端团队半年的活，做成一次可私有部署的交付（省人力/省周期）
3. 建库即得 API：业务 / AI 团队不写后端，也能上线数据服务（效率/赋能）
4. 数据不出机房的数据后端（私有化 / 信创可选）（数据主权，机会型）

整页板块结构：首屏 Hero → 痛点 → 核心能力 → 对比表（vs 自建 / vs 公有 BaaS）→ 行业场景（三段客群卡）→ 部署与安全（私有化 / License / 审计）→ 行动召唤 CTA。

## 四、Demo 策略（三件套，非做多租户产品）

1. **Demo 视频**（必做）：5–8 分钟一镜到底，渠道转发用，客户先看再约。
2. **在线体验 sandbox**（推荐）：一套共享环境、warn 模式不设授权限制、每日重置，自助点。
3. **30 天 POC License**（临门一脚）：意向客户内网跑真实数据，到期只读降级。

## 五、合规与主体（现状）

- **网站在海外、无境内主体：短期可行**，靠渠道（境内主体）签约、开票、收人民币、离岸结算。
- 海外站不需要 ICP 备案；域名用 `.com`；**不在海外站收集境内个人信息 / 收人民币**，CTA 只做留资 + 联系渠道。
- 访问速度优化：让**渠道用其境内主体备案一个国内落地页镜像**，或站点放香港/新加坡节点 + CDN。
- 软著 / 商标尽早办（可境内代理登记），利于渠道投标背书。
- 真短板：**信创 / 央国企资质门槛**——那类单交给渠道顶资质，或等确定性大单再补境内主体。

## 六、阿里云云市场

- **不是走量引擎**：高价 + 私有化 + 要实施的产品，成交不发生在商品页。
- 价值定位：**背书 + 线索入口 + 合规回款通道**；且入驻需境内主体 + 软著（可借渠道主体上架）。
- 玩法：标准版 / 试用版上架增信获客，**私有化大单绕开抽成、走渠道线下成交**（避免云市场抽佣叠加渠道分润挤毛利）。
- 优先级：**P2 增信补充，非现在**——等有 1–2 个标杆 + 软著 + 主体路径后再上。
